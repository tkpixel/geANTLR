## 2024-05-24 - Optimizing ANTLR Token Processing & View Listeners
**Learning:** Hard-coded `String.split("\r?\n", -1)` in a hot loop (like `EditorViewModel.computeTokenStyles` for syntax highlighting) is extremely expensive since it compiles a regex and allocates a string array for every single token, even though 99% of tokens do not span multiple lines. Furthermore, using `ListChangeListener` for JavaFX token and error properties forces JavaFX to eagerly compute differences when a full list replacement happens, which wastes CPU cycles if the listener simply triggers a full UI redraw anyway.
**Action:** Replaced regex-based string split with a fast path `text.indexOf('\n') == -1` to avoid overhead for single-line tokens. Replaced `ListChangeListener` with `InvalidationListener` in `EditorViewController` so that JavaFX only notifies invalidation without computing expensive structural list diffs, significantly speeding up the syntax highlighting loop. Also utilized Java 25 `Thread.ofVirtual()` for background LLM generations.
