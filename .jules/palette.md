## 2026-04-03 - Dialog Keyboard Accessibility & Tooltips
**Learning:** For quick UX wins, FXML dialogs can drastically improve their keyboard accessibility by setting `defaultButton="true"` and `cancelButton="true"` on their respective `<Button>` elements. This binds the Enter and Escape keys naturally without additional code. Also, icon-only buttons (`button-icon` style) and `MenuButton` instances require both `<tooltip>` definitions and `accessibleText`/`accessibleHelp` to be fully usable by screen readers.
**Action:** When creating or modifying JavaFX dialogs and toolbars, always include `defaultButton` / `cancelButton` for primary actions and explicit `tooltip` / `accessibleText` nodes for any button whose purpose isn't immediately conveyed by a text label.

## 2024-04-07 - Dynamic Layout Accessibility and Empty States
**Learning:** Container nodes like `FlowPane` that act as dynamic toolbars or suggestion areas can leave users confused when empty, as there is no visual indication of their purpose. Using a placeholder `Label` with `Styles.TEXT_MUTED` clarifies intent. Furthermore, when dynamically instantiating interactive UI components (like suggestion buttons) via code instead of FXML, it is critical to explicitly call `setAccessibleText()`, `setAccessibleHelp()`, and `setTooltip()` during construction.
**Action:** Always provide a visual placeholder (e.g., "No suggestions available") for dynamically populated layout nodes when they are empty, and ensure any dynamically created buttons are properly instrumented with accessibility attributes before adding them to the scene graph.

## 2024-05-19 - Button Visual Feedback for Async Operations
**Learning:** During long-running operations (like loading an ANTLR grammar), replacing a button's icon with a `ProgressIndicator` of the same size (e.g., `setPrefSize(16, 16)`) and binding its disabled state provides excellent visual feedback without layout shifting. Coupled with complete accessibility attributes (`accessibleText` and `accessibleHelp`), this dramatically improves UX.
**Action:** Whenever a button triggers an async task, bind its `disableProperty` to the task's active state and conditionally swap its `graphic` with a small `ProgressIndicator`, ensuring to restore the original graphic when done. Make sure buttons also explicitly define `accessibleText` for screen readers.
